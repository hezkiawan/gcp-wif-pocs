# X.509 mTLS & Google Cloud Workload Identity Federation (WIF) PoC

## Purpose

This repository demonstrates a **Zero-Trust authentication architecture** using **X.509 Mutual TLS (mTLS)** and **Google Cloud Workload Identity Federation (WIF)**.

The objective of this Proof of Concept (PoC) is to show how a VM, bare-metal, or on-premises Go application can securely authenticate to Google Cloud **without storing a long-lived Service Account JSON key (`service-account.json`)**.

Instead, authentication is performed using:

- X.509 client certificates for workload identity
- Google Workload Identity Federation (X.509 Provider)
- Mutual TLS (mTLS)
- Service Account Impersonation
- Google Application Default Credentials (ADC)
- Firebase Admin SDK

This results in a **secretless authentication flow**, where temporary Google credentials are generated dynamically from the workload's certificate.

---

## Important Production Note

> **Simulation vs. Production**
>
> This repository creates its own Root Certificate Authority (CA) using OpenSSL solely for demonstration purposes.
>
> In production, the Root CA would typically be operated by an enterprise PKI such as:
>
> - Sectigo
> - Microsoft Active Directory Certificate Services (AD CS)
> - HashiCorp Vault PKI
> - AWS Private CA
>
> Google Cloud would trust that enterprise Root CA through its Trust Store, allowing workload certificates issued by that CA to authenticate through Workload Identity Federation.

---

## Architecture Overview

Unlike the OIDC/JWT approach, X.509 federation relies on **Mutual TLS (mTLS)**.

The workload is provisioned with an X.509 client certificate containing the required `clientAuth` extension.

During authentication, **Google Application Default Credentials (ADC)** automatically presents this certificate to **Google Security Token Service (STS)** over mTLS. Once the certificate is validated against the configured Trust Store, Google impersonates the configured Service Account and returns temporary Google credentials.

## Authentication Summary

The authentication process consists of the following stages:

1. The workload is provisioned with an X.509 client certificate.
2. The application initializes the Firebase Admin SDK.
3. Google Application Default Credentials loads `wif-config.json`.
4. ADC establishes an mTLS connection with Google STS.
5. Google validates the certificate chain against the uploaded Trust Store.
6. Google extracts certificate attributes (e.g. Common Name).
7. IAM Attribute Mapping resolves the workload identity.
8. Google impersonates the configured Service Account.
9. Temporary Google credentials are returned.
10. Firebase Admin SDK authenticates every Firestore request automatically.

---

## Trust Store Explained

Unlike OIDC federation, where Google trusts a JWT issuer, X.509 federation establishes trust through a **Root Certificate Authority (CA)**.

The uploaded Trust Store contains one or more trusted Root CA certificates.

Any workload certificate chaining back to one of these trusted roots may authenticate, subject to the configured IAM attribute mappings and conditions.

For this PoC, the Root CA is generated locally using OpenSSL.

# IMPLEMENTATION

## Step 1 — Generate the Certificates

Generate the simulated Root CA.

```bash
openssl req -x509 -new -sha256 -newkey rsa:2048 -nodes \
-days 3650 \
-subj "//CN=Sectigo-Sim-Root" \
-config cert_config.cnf \
-extensions ca_exts \
-keyout root.key \
-out root.cert
```

Generate the workload Certificate Signing Request (CSR).

```bash
openssl req -new -sha256 -newkey rsa:2048 -nodes \
-subj "//CN=my-local-vm" \
-config cert_config.cnf \
-keyout workload.key \
-out workload.req
```

Sign the workload certificate.

```bash
openssl x509 -req \
-CA root.cert \
-CAkey root.key \
-set_serial 1 \
-days 365 \
-extfile cert_config.cnf \
-extensions leaf_exts \
-in workload.req \
-out workload.cert
```

---

## Step 2 — Create the Trust Store

```bash
export ROOT_CERT=$(cat root.cert | sed 's/^[ ]*//g' | sed -z '$ s/\n$//' | tr '\n' '$' | sed 's/\$/\\n/g')

cat << EOF > trust_store.yaml
trustStore:
  trustAnchors:
    - pemCertificate: "${ROOT_CERT}"
EOF
```

---

## Step 3 — Configure Google Cloud WIF

Export project variables.

```bash
export PROJECT_ID="YOUR_PROJECT_ID"
export PROJECT_NUMBER="YOUR_PROJECT_NUMBER"
export SA_EMAIL="YOUR_SERVICE_ACCOUNT@${PROJECT_ID}.iam.gserviceaccount.com"
```

Create the Workload Identity Pool.

```bash
gcloud iam workload-identity-pools create x509-sim-pool \
--project="${PROJECT_ID}" \
--location="global" \
--display-name="X509 Simulation Pool"
```

Create the X.509 Provider.

```bash
gcloud iam workload-identity-pools providers create-x509 x509-sim-provider \
--project="${PROJECT_ID}" \
--location="global" \
--workload-identity-pool="x509-sim-pool" \
--trust-store-config-path="trust_store.yaml" \
--attribute-mapping="google.subject=assertion.subject.dn.cn"
```

Grant Service Account impersonation.

```bash
gcloud iam service-accounts add-iam-policy-binding "${SA_EMAIL}" \
--project="${PROJECT_ID}" \
--role="roles/iam.workloadIdentityUser" \
--member="principal://iam.googleapis.com/projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/x509-sim-pool/subject/my-local-vm"
```

---

## Step 4 — Generate ADC Configuration

```bash
gcloud iam workload-identity-pools create-cred-config \
projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/x509-sim-pool/providers/x509-sim-provider \
--service-account="${SA_EMAIL}" \
--credential-cert-path="$(pwd)/workload.cert" \
--credential-cert-private-key-path="$(pwd)/workload.key" \
--output-file="wif-config.json"
```

---

## Step 5 — Execute the Application

```bash
export GOOGLE_APPLICATION_CREDENTIALS="$(pwd)/wif-config.json"

go run main.go
```

Expected output:

```text
Success! Document written to Firestore using an X.509 client certificate.
```

## How Google Authentication Works

The Go application contains **no authentication logic**.

Calling:

```go
firebase.NewApp(...)
```

automatically triggers:

```text
firebase.NewApp()
│
Application Default Credentials
│
GOOGLE_APPLICATION_CREDENTIALS
│
wif-config.json
│
Load X.509 Certificate
│
Mutual TLS Handshake
│
Google Security Token Service
│
Certificate Validation
│
Attribute Mapping
│
Service Account Impersonation
│
Temporary Google Access Token
│
Firestore
```

All authentication occurs transparently beneath the Firebase Admin SDK.
